# Persistent naming

Status: **normative** (M6). Source requirements: 6. Implemented by `tcad-naming` (IDs, resolver,
queries) and `tcad-build` (which feeds it the history of every operation).

A reference to a face or an edge must keep meaning the same geometry when upstream parameters change.
There are three ways to refer to geometry, tried in this order: a **tag**, a **semantic ID**, a
**query**. A reference that does not resolve stops regeneration at that feature (`E3xxx`); the
resolver never silently picks something else.

## Semantic IDs of faces

Every face a feature creates gets an ID `<feature>.<role>`, derived from history, never from kernel
numbering. The role may carry a generator in parentheses: `boss.side(profile.r1.top)`.

| Created by | Roles |
| --- | --- |
| `extrude`, `revolve`, `sweep`, `loft` | `cap_start` (the profile, at the start), `cap_end`, and `side(<segment>)` for the face generated by a profile segment. A full turn of `revolve` has no caps. |
| `hole` | `wall`, `floor`, `cbore_wall`, `cbore_floor`, `csk` (the cone). With several positions: `p1.wall`, `p2.wall`, ... |
| `rib` | `cap_start`, `cap_end`, `side(top0)`, `side(top1)`, ... (the centerline segments), `side(foot)`, `side(end0)`, `side(end1)` |
| `fillet`, `chamfer` | `face(<generator of the edge>)`: the face made from an edge, for example `round.face(boss.cap_end & boss.side(s.r.bottom))` |
| `shell` | `inner(<face>)`: the inner wall facing a face that stayed; `rim(<generator of the edge>)`: the rim around an opened face |
| `linear_pattern`, `circular_pattern` | `<pattern>.i<k>.<role of the copied face>`: instance `k` (1 is the original and keeps its own names). A pattern of a pattern prefixes both: `rows.i2.i3.wall` |
| `mirror` | `<mirror>.<role of the copied face>` |

**Segment names** in `side(...)` are `<sketch>.<entity>` for a sketch entity, with the curve role for
multi-segment entities: `profile.c1`, `profile.r1.top`. Rectangle roles are `bottom`, `right`, `top`,
`left`; polygon edges `e0`, `e1`, ...; slot sides `right`, `end_cap`, `left`, `start_cap`. Inline
profiles use `rect.bottom` ... `rect.left` and `circle`.

A face that no rule names (for example a corner patch where fillets meet) is called
`<feature>.extra`. Its name is stable but cannot be told apart from similar faces except by ordinal.

### What later features do to IDs

* **Trimmed, moved or unchanged** faces keep their IDs.
* **Merged** faces (two faces on one surface joined by a boolean) keep the ID of the earliest
  contributing feature as the primary ID; the others become **aliases**: both names resolve to the
  merged face.
* **Split** faces (one face cut in two by a later feature) share the ID and are told apart by an
  ordinal `#k` (1-based), ordered by the kernel-independent rule: centroid x, then y, then z, then
  area (all rounded to 1e-6 mm). A split ID without ordinal is `E3002` and lists the candidates.
  The ordinal appears as soon as more than one face carries the same ID.

## Edges

An edge is named by the faces it joins: `edge(<face> & <face>)` (the order does not matter; aliases
are accepted). `edge(a)` names edges of a single face. When several edges join the same faces
(for example two circles) they are told apart by ordinal, ordered by midpoint position. A face
reference where edges are wanted stands for all edges of the face.

## Tags

`tag front_hole = pin_hole.wall` binds a stable, human name to a face or edge. A tag is resolved
where it is declared and **again** each time it is used, from the reference it was bound to. Tags
may refer to tags (a cycle is `E3001`). An ordinal after a tag, `tag#2`, selects from what the tag
denotes.

## Queries

`query(faces, normal=+Z, created_by=boss)` and `query(edges, parallel_to=+X, adjacent_to=boss.cap_end)`.
All filters must hold. Results are ordered by position, not by kernel numbering.

| Filter | Value | Selects |
| --- | --- | --- |
| `type` | `plane`, `cylinder`, `cone`, `sphere`, `torus`, `bspline` (edges: `line`, `circle`, `ellipse`, `bspline`) | |
| `normal` | direction (`+Z`, `(0, 0, 1)`) | planar faces with this outward normal |
| `parallel_to` | direction, axis or plane | planar faces with a normal parallel to it; straight edges parallel to it |
| `axis` | direction or axis | cylinders, cones, tori with this axis |
| `radius` | length | cylinders, cones, spheres, tori, circular edges |
| `created_by` | feature name | entities with an ID from that feature (edges: next to such a face) |
| `adjacent_to` | face reference | faces sharing an edge with it; edges of it |
| `nearest` | point | the single closest entity |
| `largest`, `smallest` | flag | greatest or least area (faces) or length (edges) |

The caller states how many entities it needs: one face to put a sketch or hole on, at least one edge
to fillet. A query that selects nothing is `E3003`; one that selects the wrong number is `E3003`
with the candidates listed (up to eight). Unknown filters and invalid values are `E3004`. Querying
vertices is not supported yet (`E5003`).

## Resolution and failure

Order: tag, then semantic ID, then (if written as `query(...)`) query. On failure:

| Code | Meaning |
| --- | --- |
| `E3001` | the reference does not exist in the current shape; the message and a fix hint give the nearest names |
| `E3002` | the reference names several entities (a split face) and needs an ordinal |
| `E3003` | a query matched the wrong number of entities |
| `E3004` | an unknown or malformed query filter |
| `E3005` | the reference denotes the wrong kind of entity (an edge where a face is needed, ...) |

## Topology map

After every feature the manifest (`spec/bundle.md`) records the faces and edges of the result with
their primary ID, aliases, surface or curve type, area or length and position, so tools can show
and diff names without a kernel. `tcad refs <part>` prints each reference of the source with what it
resolves to, and with the reason when it does not.

## Robustness tests

`corpus/nam_*` parts declare **sweeps**: sets of parameter values (in ranges that keep the topology)
for which the part must build, resolve every reference, keep exactly the same set of names and match
a closed-form volume and bounding box.
